# Делать

## Словарь постобработки

Самое ценное из оставшегося: по августовскому замеру словарь снимает
**6,1 п.п. WER** — больше, чем дала бы смена движка. Проблема не в обычной
русской речи, а в рабочих терминах, и ошибки стабильны — например, распознаётся
`кубер нетис` вместо `Kubernetes`, `ABC 12 3` вместо номера задачи `ABC-123`,
`пост грес кул` вместо `PostgreSQL`, `ноушен` вместо `Notion`.

**Ключевой принцип: не пары «ошибка → исправление», а список правильных
терминов.** Модель коверкает по-разному каждый раз, перечислять варианты
бесполезно. Вместо этого:

1. **Фонетическое притягивание.** Список из одних правильных терминов
   (30–50 слов: сервисы, префиксы задач, имена). Постобработчик находит в
   распознанном тексте слова, фонетически близкие к термину (Левенштейн на
   фонетическом представлении, с учётом транслитерации ru/en), и заменяет.
   `кубер нетис`, `кубернетес` и `Kuber Netis` ложатся на `Kubernetes` одной
   строчкой списка. Порог близости консервативный: ложная замена хуже
   пропущенной.
2. **Правила-шаблоны для структурного.** Номера задач, суммы, версии — это
   не словарь, а регулярки: «`ABC` + пробелы/мусор + цифры → `ABC-цифры`»
   чинит все номера сразу. Таких правил нужно ~5.
3. **Список терминов не составлять руками** — вытащить частотные термины
   из личной базы заметок и истории диктовок. Пополнение — одна
   строка на новый термин.

**Где живёт.** В воркере, после `распознать()`: микросекунды на фразу,
задержки не добавляет. Отдельный модуль со своими тестами.

**Как проверять.** На трёх эталонных записях в `~/Chirper-замеры` через
`замер_точности.py сравнить` — цифра до/после. База без словаря: 21,3%.
Ожидание: минус ~6 п.п. Обязательно смотреть и на ложные замены: WER может
спрятать случай, когда словарь «починил» правильное слово.

**Потом, если захочется большего:** прогон текста через маленькую локальную
LLM со списком терминов в промпте — правит по контексту, но +0,5–1 с
задержки и новая зависимость. Начинать не с этого.

## Конвейер распознавания во время записи

Сейчас распознавание начинается после «стоп»: минутная диктовка ждёт ~2 с.
Куски по 20 с можно распознавать, пока человек ещё говорит, — после «стоп»
останется только хвост, задержка перестанет расти с длиной записи.

Цена — переделка протокола воркера и записи в Swift (буфер кусками вместо
одного файла). Стал актуальнее после режима фиксации: длинные диктовки
теперь удобно наговаривать, пусть будут и быстрыми. Сюда же — индикация
прогресса распознавания многоминутной записи (сейчас похоже на зависание).

# Отложено

## Убрать прогрев при старте записи

Прогрев при старте записи ([Chirper.swift:1707](native/Chirper.swift#L1707))
— страховка, оставленная сознательно на случай задержки после простоя или
сна. Задержка себя не проявила ни разу: после перехода на ONNX приложение
отзывается сразу, в том числе после сна. Страховка больше не нужна — строку
можно убирать.

Заодно закрылся и замер поведения при выходе из сна: он затевался ради
задержки, которой нет.

Прогрев при старте демона не трогать: он закрывает ленивую инициализацию
onnxruntime.

## Подпись и нотарификация

Сборка подписана ad-hoc (`codesign --sign -`), поэтому у любого другого
человека macOS блокирует первый запуск: на macOS 15+ нужно идти в
**Privacy & Security → Open Anyway**, на 13–14 хватает «Открыть» из
контекстного меню.

Для раздачи паре человек это терпимо (инструкция есть в README и в описании
релиза). Снять ограничение можно **только** через Apple Developer Program —
99 $/год: и сертификат Developer ID, и доступ к нотарификации выдаются
исключительно участникам программы. Бесплатные пути проверены и не годятся —
сертификат «Apple Development» из бесплатного Apple ID предназначен для
запуска на своих устройствах при разработке, самоподписанный сертификат
Gatekeeper не знает, а `xattr -d com.apple.quarantine` требует, чтобы
получатель сам снимал защиту командой в терминале.

Если однажды понадобится: `notarytool submit` + `stapler staple` в
[собрать_app.sh](собрать_app.sh) после `codesign`. Делать, если приложение
пойдёт шире круга знакомых.
